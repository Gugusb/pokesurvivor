# 远征输出平衡记录

管理员从排行榜进入管理页面，选择「远征输出记录」。支持用户名、客户端版本、起止天数、非调试局筛选。页面显示最近50条，展开可查看完整快照；JSON/CSV导出当前筛选下全部保留记录（最多10000条），包括峰值队伍、羁绊、技能、装备和伤害来源。CSV内复杂字段以JSON字符串保存。

## 统计口径

- 每个远征战斗日一条记录。全清、普通战超时生还、死亡与主动结束分别标记为 `cleared/survived/defeat/abandoned`。非战斗日没有DPS，正常结束前只保留在当前页内存。
- 平均DPS为本场实际生命与护盾伤害总和除以战斗游戏时间。复用伤害账本，不计过量伤害；宝可梦、羁绊及特性拆分不重复计入总伤害。
- 峰值是滑动5个游戏秒内伤害/5，按模拟步更新。暂停、界面等待和真实墙钟不计入；倍速改变真实耗时，不改变时间单位。短于5秒的战斗按实际时长计算，并明确记录 `peak.seconds`。这是口径一致性，不保证不同模拟帧率/倍速产生完全相同战况。
- 保存开战、结束、峰值三份独立快照。峰值快照时间是该窗口结束时刻；均值/峰值相同时保留首次到达的快照。
- 快照含训练家/宝可梦等级、金币、人口、上阵队伍的平均品质和星级及分布、各羁绊人数/层数/生效档位，以及队长、队员和候补的物种、星级、品质、是否上阵/倒下、属性/蛋组、特性、技能等级/专精/超限/槽位、携带物、临时增益和当时属性。总体品质统计以出战队伍（含队长和已倒下成员）为分母，候补单独列出。
- 快照优先记录出战成员，再记录候补，默认最多32名；超过时 `truncated=true`，总体人数和品质分布仍按全队计算。`sources`最多保留128个伤害来源。版本取客户端设置页版本，便于区分数值迭代。

## 上传与数据范围

客户端模块为 `js/systems/expedition-recorder.js`。每场结束异步上传到 `POST /api/run/dps`，使用已登录账号和真实服务端对局ID。失败不会中断游戏、修改金币或影响存档；本机按账号保留最近100条历史和最多100条待发送记录，在线、新开远征或重新回到页面时重试。暂未建立的服务端对局保留等待后续重试。游客仅保存在本机，不汇总到后台。强制关闭页面可能缺少尚未结束战斗的记录；本机存储容量不足时不保证持久保留。

服务器 `server/expedition-recorder.cjs` 校验数值、DPS与伤害/时间的一致性、结构深度及体积；单条上限128KiB。账号只能上传属于自己的远征ID，对已结束对局允许补传。SQLite表 `expedition_dps` 以 `(run,day)` 去重，重试不重复生成或覆盖记录。独立于玩家存档与排行榜，不发奖励，不推进对局状态。

服务器默认保留最近90天、最多10000条，每次成功上传时清理超限记录。账号注销及关联对局删除会清除相应数据。注销账号也清理该账号的本机输出记录。

这些数据是经过结构校验的**客户端遥测**，不是服务端验证的伤害成绩，不能作为排行或反作弊证据。后台显示来源和非标准标记，默认排除调试局；如果服务端后来把整局标记为非标准，查询时也会排除。均值和峰值适合后续分析，需要结合版本、事件、天数、队伍资源及快照进行比较。

## 后台接口与验证

`GET /api/admin/expedition-dps` 仅管理员可读，响应 `Cache-Control: no-store`。参数包括 `q/version/dayFrom/dayTo/uid/run/clean`，用 `before` 游标分页，`limit`最大500。JSON和CSV由管理页面在授权查询后生成，不提供公开下载地址。

`node --test tools/test_dps_recorder.cjs tools/test_dps_server.cjs` 验证平均/滑窗峰值、不可变快照、暂停和倍速口径、伤害归因、断网重试、账号隔离、权限、幂等补传、数据校验、筛选、保留上限和注销清理。`node tools/qa_dps_recorder.cjs` 使用隔离内存SQLite和Edge验证实际页面自动上传、管理员详情及筛选、JSON/CSV下载；产物写入忽略目录 `tools/cache/`，不含真实玩家数据。

部署时按既有自建服务流程备份数据库并重启服务以创建新增表；本次开发只运行本地隔离验证，不代表已部署到公网服务器。

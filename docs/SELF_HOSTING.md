# 自建账号、排行榜与好友服务（v0.20.0）

**v0.20.0 暂时关闭邀请联机**：正式服务不提供创建、加入、邀请或开始房间的接口，主菜单保留单人游玩。旧 P2P 实现保留供后续恢复，`coopEnabled` 仅由内部回归测试创建隔离服务时开启，不提供公网环境变量开关。

新增孵蛋屋和免费好友赠礼，均需登录自建账号；纯静态／游客模式没有这些服务器持久化功能。孵蛋计时、亲本快照、好友参与限制、邀请有效期、奖励随机与领取事务由同源服务及 SQLite 管理，不需要额外进程、定时任务或战斗中转。正常启动会自动创建新增表，旧账户与存档保留；升级前先用下文备份命令保留数据库。

孵蛋最长 12 小时，离线和停服期间仍计时；同一亲本的邀请持续有效，撤回或更换主亲本使旧邀请失效。开始后须等完成并领取，不能暂停／中止。好友双方各自领取，未领取的结果不会因对方已收获而消失。自行继承 1 项、好友继承 2 项个体值，图鉴继续保留每项最佳值。

礼物按北京时间 00:00 切日，每人每日向最多 10 位不同好友各送一份，不扣除物品；收礼者可离线积累并逐份领取。奖励为 60% 获得 200～500 宝可梦币、25% 获得 1 张单抽券、15% 获得 1 枚特性宝石。收到的礼物不设过期，收件箱每次展示最早 100 份，领取后继续显示其余。领取检查存档修订号并在同一事务中发奖、标记已领取，防止重复发奖及覆盖另一设备的进度。

v0.16.0 曾按 **4 核、4GB、3Mbps 出口**的预算改为 P2P 战斗直连。旧中转版完整保存在标签 `v0.15.0` 和分支 `codex/relay-v0.15`；`main` 保留 P2P 代码，当前版本暂不开放联机。原连接与回退说明见 [P2P.md](P2P.md)。

## 本地启动

需要 Node.js 24.14 或更新的 24.x。游戏和 API 同源部署，不再需要 Firebase、Google 登录或原作者的 TURN 服务。

```powershell
Set-Location 'D:\GuguFiles\AIWorkspace\PokeSurvivor'
npm --prefix server ci
node server/server.cjs
```

打开 http://127.0.0.1:8000/；源码调试用 `/dev.html`。默认只监听回环地址。端口由 `PORT` 指定。数据库默认在 `server/data/game.sqlite`，可用 `DB_FILE` 指向独立磁盘路径。

v0.20.4 起，正式网页的账号服务断网、超时、报错或响应异常时，仍保持服务器账号模式，登录页提供重试及游客试玩，不再自动恢复／创建同名本地账号。曾成功连接服务器的同源地址也不会因后来的 404 降级。仅 `file://`，或首次访问且 `/api/health` 明确返回 404 的回环静态试玩地址保留本地账号兼容。

旧浏览器存档不删除、不自动导入服务器。登录页可备份当前地址旧存档；`/local-save-backup.html` 为纯本地、三语备份页，不请求账号 API，不导出密码、恢复码或登录凭据。不同地址、协议和浏览器的存储互相独立。部署时可仅为该精确路径保留旧 HTTPS 域名／IP 的静态访问，其余路径仍跳转主站，方便分别备份旧入口数据；不要为旧入口开放账号 API 跨来源访问。

`python -m http.server` 仍可用于游客和旧本地账号试玩，但不提供自建账号、云存档或联网功能。**旧本地账号和存档仍保留在原浏览器、原端口中；新服务器账号单独注册，不自动把可编辑的本地勋章导入公共榜单。**

## 账号与管理

- 用户名 3～16 个字母、汉字、数字或下划线；忽略大小写，唯一且不可复用。
- 密码 8～128 位，使用独立随机盐与 scrypt 派生。数据库只保存哈希。
- 注册后显示一次随机恢复码。找回时使用用户名、恢复码、新密码；成功后原恢复码和全部旧登录会话失效，并显示新恢复码。无需邮箱、Google 或第三方身份服务。
- 随机登录凭据使用 HttpOnly、SameSite=Strict Cookie；HTTPS 配置下还会设置 Secure。数据库只保存凭据摘要。
- 封禁状态和角色保存在账号表，与玩家存档分离。封禁撤销所有会话、踢出联机、阻止登录及恢复码找回；不会被清空存档重置。
- 注销需验证密码，删除存档、好友和成绩；保留不可登录、不可复用的账号标识和管理审计。
- 没有公开的“首位注册即管理员”规则。先在游戏注册自己的账号，再通过服务器命令行授权：

```bash
# 在项目根目录运行；DB_FILE 应与服务使用同一数据库路径。
node server/admin.cjs promote YOUR_USERNAME
node server/admin.cjs users
node server/admin.cjs demote YOUR_USERNAME
```

管理员重新登录后，在排行榜的“用户管理”中搜索用户、封禁/解封、查看举报、删除八星时间成绩及忽略举报。数量榜直接来自勋章记录；有争议时先封禁并检查数据库备份，不允许通过前端任意填分。

## 两种排行榜

1. **满勋章通关数量榜**：集齐 1～8 星勋章的宝可梦图鉴编号数。进化家族的每个编号分别计算，包括分支进化；例如伊布家族当前共有 9 个编号，集齐后计 9 只。胜利时整条家族获得对应星级勋章。继承勋章不会凭空复制其他形态的生存时间。
2. **冒险得分榜**：每个账号所有已解锁难度中的单人最佳得分，包含击杀、生存及成功事件分，再乘 0.8～10 倍难度得分倍率。正常一／二倍速均参与，调试和未通过验证的对局除外；不要求本局通关。分数由服务器复用共同公式计算，详见 [SCORE_AND_BOSSES.md](SCORE_AND_BOSSES.md)。旧八星时间表保留归档，不猜测缺失事件／精英计数，不自动换算新分数。联机不与单人榜混排。

同分按首次达到该成绩的时间，再按账号标识稳定排序。界面显示前 100 名和当前账号的准确名次，实时重新请求，不使用旧的跨账号长缓存。普通存档上传不能写入勋章、难度解锁、双倍领取凭据和排行榜成绩。

每局都有独立 ID，开始前向服务器建立记录；每 10 秒发送心跳，限制计时、倍速和请求容差，结束后只能结算一次。上传错误明确提示；失败的结束请求保存在本机，排行榜“刷新”可重试。超过连接验证窗口的请求会拒绝，不会被冒充为成功。

存档使用服务器版本号比较，其他设备已保存时返回冲突，不会静默覆盖。未同步副本保存在当前浏览器 `ps.selfhost.<uid>`，不要清理浏览器数据。重新载入时优先使用服务器存档；匹配版本的未同步本机修改可以恢复。不同设备的消费不会用“取最大值”自动合并。

挂机结算、通关勋章和首次双倍领取均在服务器数据库事务中进行。服务器使用自己的时钟和挂机结算游标。金币、抽奖及一般收藏目前仍接受经过结构/范围检查的客户端存档，见下方限制。

## 联机

浏览器通过 WebRTC DataChannel 与房主直接交换战斗帧，房主运行敌人和世界模拟。服务器 WebSocket 只负责经过身份、房间和收件人校验的握手，以及服务器发起的开局通知；客户端 `net` 战斗转发请求会被拒绝，只有房主与队员之间可以交换握手。好友邀请有效期 3 分钟，最多 4 人，服务器检查双向直连就绪后才允许开局。

不配置 TURN，也不提供 WebSocket 战斗中转回退。不能穿透的校园网、公司网、移动网络或路由器组合可能无法联机；会明确显示失败并允许重试。默认公共 STUN 只用于地址发现；`STUN_URLS` 可配置最多四个逗号分隔的 `stun:`/`stuns:` 地址，`turn:` 不会被采用。

大消息通过有序可靠通道分片传输。短暂 P2P 故障尝试重新协商并同步世界，约 20 秒仍未恢复则视为离队；信令连接关闭后房间保留约 15 秒，需继续保持轻量服务器连接和对局心跳才能记录成绩。房主长期断线或服务重启会结束队伍，没有房主迁移。队友可能获知彼此的公网 IP，已更新隐私说明。

## Linux 部署与备份

建议 Ubuntu 24.04 LTS 或 Debian 12/13。安装符合版本要求的 Node.js、Caddy，再复制项目及素材，执行 `npm --prefix server ci --omit=dev`。

- 服务用专用低权限用户运行。参考 `server/pokesurvivor.service.example`。
- `PUBLIC_ORIGIN=https://你的域名` 必须与访问入口一致，才能进行来源校验并启用 Secure Cookie。
- `TRUST_PROXY=1` 只在回环地址后接可信反向代理时使用，以取得正确客户端 IP，避免所有用户共用一个限流桶。
- `server/Caddyfile.example` 提供 HTTPS 和 WebSocket 反向代理；Node 默认端口不向公网开放。
- 单进程与 SQLite WAL 起步，不要用多个独立 Node 实例、多个本地 SQLite 文件组成“集群”。需要横向扩容时迁移 PostgreSQL，并把会话、房间与发布订阅迁到共享服务。
- `/api/*` 不可由 CDN、反向代理或 Service Worker 缓存；`/ws` 不可缓存。PNG、字体等素材适合 CDN。Caddy 可压缩 HTML、JS、CSS。
- 部署前在测试环境验证域名、HTTPS、Cookie、跨设备登录、WebSocket、断线、数据恢复。当前没有部署任何公网服务。

数据库备份必须保存在网页根目录之外，限制读取权限，并加密复制到另一台机器或对象存储。建议每日一次、保留 7～30 份；重大升级前额外备份。使用 SQLite 快照，不直接复制运行中的主文件而遗漏 WAL：

```bash
DB_FILE=/var/lib/pokesurvivor/game.sqlite node server/backup.cjs /private/backups/game-20261018.sqlite
```

恢复时先停止服务，将已验证备份恢复到 `DB_FILE`，检查文件权限后再启动。会话属于敏感数据，备份不得公开下载或提交到 Git。

## 4 核 4GB、3Mbps 的使用边界

**一万注册账号不等于一万人同时在线。** 该配置适合从小规模 P2P 服务起步，不能据此保证一万并发。战斗帧带宽转移到玩家网络，服务器仍承担握手、心跳、存档、排行榜、登录和网页素材。

| 项目 | 当前安排 |
|---|---|
| 应用 | 单 Node.js 进程、SQLite WAL；不需要额外部署 TURN |
| 对局心跳 | 每 10 秒仅下发变化的勋章记录、难度及挂机游标，不返回整份存档 |
| 在线状态 | 每 30 秒轻量更新，不重复提交完整存档；校验版本以防跨设备覆盖 |
| 握手配额 | 每账号每分钟最多 240 条、96 KiB 输入；单条最大 24 KiB，SDP 最大 16 KiB；不接受任意战斗消息 |
| 3Mbps 瓶颈 | 理论总出口约 375 KB/s，实际还需扣除协议开销；集中首次加载素材最容易占满 |
| 静态资源 | 用 Caddy 压缩 JS/CSS/HTML，保留浏览器缓存；多人公开试玩时建议素材使用 CDN，API/WS 不缓存 |
| 运维 | 每日异机备份，监控出站流量、请求延迟、内存与磁盘；按真实峰值决定限制人数 |

可复现的控制面合成测试：`node tools/benchmark_p2p.cjs 100`。本机创建 10,000 个内存账号、100 个 WebSocket 连接和 75 组模拟握手，测得握手阶段及空闲期平均 WebSocket 出口约 0.3084 Mbps、在线状态响应平均 198 字节、排行榜 P95 19.64 ms、RSS 101.3 MiB；随后 8 秒没有新增握手消息。**没有模拟公网 NAT、真实云服务器、全部 HTTP 流量和集中加载素材，不是并发容量承诺。**

四个实际浏览器的独立测试已验证真实 WebRTC、6 万字符分片、升级选择、重连、房主断线和零战斗中转；一次普通对局心跳响应为 292 字节。真实房主仍需要向队员上传世界状态：若每份 5 KB、15 Hz、三名队员，约 1.8 Mbps 上传，后期可能更高。

v0.15.0 的 28.32 Mbps 合成转发结果只适用于旧中转架构；不能用它估算本版 P2P 服务器。旧测试脚本 `tools/benchmark_server.cjs` 仅允许在旧版本运行。

## 已知限制

- 服务器控制账号、勋章与成绩写入，并做独立对局时钟校验；**还没有服务端重演完整战斗**。仍信任客户端的部分战斗事实，不能宣称彻底防作弊。普通货币/收藏的所有奖励来源也还没有完整迁入服务端经济账本。
- 本版不自动把旧本地存档或原作者的 Firebase 用户迁入公共榜单，也不复用其管理员、云项目或中转服务。
- 已验证同机四个独立浏览器会话的真实 P2P 及合成信令负载。尚未在公网跨运营商、移动网络、高延迟或目标云服务器上验证直连成功率、稳定性和容量。
- 没有房主迁移；不保证断线期间所有瞬时战斗奖励都可重放。长期断线或服务重启结束当前房间。
- 本版没有自动部署、付费购买或修改生产服务。

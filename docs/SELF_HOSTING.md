# 自建账号、排行榜与联机服务（v0.15.0）

## 本地启动

需要 Node.js 24.14 或更新的 24.x。游戏和 API 同源部署，不再需要 Firebase、Google 登录或原作者的 TURN 服务。

```powershell
Set-Location 'D:\GuguFiles\AIWorkspace\PokeSurvivor'
npm --prefix server ci
node server/server.cjs
```

打开 http://127.0.0.1:8000/；源码调试用 `/dev.html`。默认只监听回环地址。端口由 `PORT` 指定。数据库默认在 `server/data/game.sqlite`，可用 `DB_FILE` 指向独立磁盘路径。

`python -m http.server` 仍可用于游客和旧本地账号试玩，但不提供自建账号、云存档或联网功能。**旧本地账号和存档仍保留在原浏览器、原端口中；新服务器账号单独注册，不自动把可编辑的本地勋章导入公共榜单。**

## 账号与管理

- 用户名 3～16 个字母、汉字、数字或下划线；忽略大小写，唯一且不可复用。
- 密码 8～128 位，使用独立随机盐与 scrypt 派生。数据库只保存哈希。
- 注册后显示一次随机恢复码。找回时使用用户名、恢复码、新密码；成功后原恢复码和全部旧登录会话失效，并显示新恢复码。无需邮箱、Google 或第三方身份服务。
- 随机登录凭据使用 HttpOnly、SameSite=Strict Cookie；HTTPS 配置下还会设置 Secure。数据库只保存凭据摘要。
- 封禁状态和角色保存在账号表，与玩家存档分离。封禁撤销所有会话、踢出联机、阻止登录及恢复码找回；不会被清空存档重置。
- 注销需验证密码，删除存档、好友和成绩；保留不可登录、不可复用的账号标识和管理审计。
- 没有公开的“首位注册即管理员”规则。先在游戏注册自己的账号，再通过服务器命令行授权：

```bash
# 在项目根目录运行；DB_FILE 应与服务使用同一数据库路径。
node server/admin.cjs promote YOUR_USERNAME
node server/admin.cjs users
node server/admin.cjs demote YOUR_USERNAME
```

管理员重新登录后，在排行榜的“用户管理”中搜索用户、封禁/解封、查看举报、删除八星时间成绩及忽略举报。数量榜直接来自勋章记录；有争议时先封禁并检查数据库备份，不允许通过前端任意填分。

## 两种排行榜

1. **满勋章通关数量榜**：集齐 1～8 星勋章的宝可梦图鉴编号数。进化家族的每个编号分别计算，包括分支进化；例如伊布家族当前共有 9 个编号，集齐后计 9 只。胜利时整条家族获得对应星级勋章。继承勋章不会凭空复制其他形态的生存时间。
2. **八星生存时间榜**：每个账号的八星单人最佳时间。要求未使用开发者模式/调试、全程一倍速、服务器认可逐级解锁、完成有效对局。时间按完整秒记录，未满一秒不计。联机可获得通关勋章，但其时间不与单人榜混排。

同分按首次达到该成绩的时间，再按账号标识稳定排序。界面显示前 100 名和当前账号的准确名次，实时重新请求，不使用旧的跨账号长缓存。普通存档上传不能写入勋章、难度解锁、双倍领取凭据和排行榜成绩。

每局都有独立 ID，开始前向服务器建立记录；每 10 秒发送心跳，限制计时、倍速和请求容差，结束后只能结算一次。上传错误明确提示；失败的结束请求保存在本机，排行榜“刷新／重试上传”可重试。超过连接验证窗口的请求会拒绝，不会被冒充为成功。

存档使用服务器版本号比较，其他设备已保存时返回冲突，不会静默覆盖。未同步副本保存在当前浏览器 `ps.selfhost.<uid>`，不要清理浏览器数据。重新载入时优先使用服务器存档；匹配版本的未同步本机修改可以恢复。不同设备的消费不会用“取最大值”自动合并。

挂机结算、通关勋章和首次双倍领取均在服务器数据库事务中进行。服务器使用自己的时钟和挂机结算游标。金币、抽奖及一般收藏目前仍接受经过结构/范围检查的客户端存档，见下方限制。

## 联机

自建 WebSocket 服务转发战斗消息，只有房间成员能发给同房间合法对象，发送者 ID 由服务器补写。好友邀请有效期 3 分钟；服务器检查房主身份、人数上限 4 和共同解锁难度，不依靠客户端人数检查。

当前仍由房主运行敌人和世界模拟。客户端上报状态和命中增加了数值、技能、装备及长度检查。短暂断线自动重连，保留房间 15 秒，重连时重新下发敌人与掉落物；超过保留时间关闭对应成员/房间。房主长期断线不迁移房主，队伍会结束。重启服务也会关闭内存中的房间，账号和成绩不会丢失。

## Linux 部署与备份

建议 Ubuntu 24.04 LTS 或 Debian 12/13。安装符合版本要求的 Node.js、Caddy，再复制项目及素材，执行 `npm --prefix server ci --omit=dev`。

- 服务用专用低权限用户运行。参考 `server/pokesurvivor.service.example`。
- `PUBLIC_ORIGIN=https://你的域名` 必须与访问入口一致，才能进行来源校验并启用 Secure Cookie。
- `TRUST_PROXY=1` 只在回环地址后接可信反向代理时使用，以取得正确客户端 IP，避免所有用户共用一个限流桶。
- `server/Caddyfile.example` 提供 HTTPS 和 WebSocket 反向代理；Node 默认端口不向公网开放。
- 单进程与 SQLite WAL 起步，不要用多个独立 Node 实例、多个本地 SQLite 文件组成“集群”。需要横向扩容时迁移 PostgreSQL，并把会话、房间与发布订阅迁到共享服务。
- `/api/*` 不可由 CDN、反向代理或 Service Worker 缓存；`/ws` 不可缓存。PNG、字体等素材适合 CDN。Caddy 可压缩 HTML、JS、CSS。
- 部署前在测试环境验证域名、HTTPS、Cookie、跨设备登录、WebSocket、断线、数据恢复。当前没有部署任何公网服务。

数据库备份必须保存在网页根目录之外，限制读取权限，并加密复制到另一台机器或对象存储。建议每日一次、保留 7～30 份；重大升级前额外备份。使用 SQLite 快照，不直接复制运行中的主文件而遗漏 WAL：

```bash
DB_FILE=/var/lib/pokesurvivor/game.sqlite node server/backup.cjs /private/backups/game-20261018.sqlite
```

恢复时先停止服务，将已验证备份恢复到 `DB_FILE`，检查文件权限后再启动。会话属于敏感数据，备份不得公开下载或提交到 Git。

## 一万注册用户的选型估算

**注册人数不能直接等同于同时在线人数。** 起步假设：10,000 注册用户，峰值 100～300 在线，其中同时联机 20～80 人，主要战斗计算仍在浏览器。

| 用途 | 建议 |
|---|---|
| 首台应用服务器 | 4 vCPU、8 GB RAM、100 GB 以上 SSD；Linux；可升级规格 |
| 网络 | 100～200 Mbps 可用出口起步；认真核对实际带宽保障、月流量和超额规则 |
| 流量预算 | 先按每月 3～5 TB 可用额度预留，再按真实用量调整；素材放 CDN |
| 较多同时联机（约 200 人以上） | 考虑 8 vCPU、16 GB 和 300 Mbps 以上出口；先用真实后期对局压测 |
| 数据与运维 | SQLite WAL、每日异机加密备份、进程自动重启、CPU/内存/延迟/磁盘/出站流量监控 |

本地可复现的轻量合成测试：`node tools/benchmark_server.cjs 100`。在开发机上创建 10,000 个内存数据库账号，连接 100 个本地 WebSocket 客户端，每 4 人一组，房主每秒 10 次向队友发送约 5 KB 帧，运行约 8 秒。一次测得：出口 28.32 Mbps、排行榜请求 P95 51.68 ms、进程 RSS 127.9 MiB、事件循环 P99 41.84 ms。这个进程也包含负载发生器，**结果不是目标云服务器的容量承诺，也没有模拟长时间后期战斗**。

真实客户端一般每秒 15 次同步，后期敌人多时帧会增大。100 名同时联机玩家，按上述帧大小折算约 45 Mbps，再加协议、玩家上报和素材下载；因此不要购买只有 3～10 Mbps 出口的套餐。月流量取决于平均联机人数与游玩时长：平均每人出站 50 KB/s × 100 人 × 每天 2 小时 × 30 天约 1.08 TB，另加素材访问。并非每个注册玩家全天在线。

供应商对“峰值带宽”的定义和流量计费不同；例如[阿里云轻量规格](https://www.alibabacloud.com/help/en/simple-application-server/product-overview/instance-families/)列有 4 vCPU/8 GiB、最高 200 Mbps 的规格，但峰值不能当作始终保证的带宽。购买前以目标地域、账号控制台的实时规格和续费价格为准。

## 已知限制

- 服务器控制账号、勋章与成绩写入，并做独立对局时钟校验；**还没有服务端重演完整战斗**。仍信任客户端的部分战斗事实，不能宣称彻底防作弊。普通货币/收藏的所有奖励来源也还没有完整迁入服务端经济账本。
- 本版不自动把旧本地存档或原作者的 Firebase 用户迁入公共榜单，也不复用其管理员、云项目或中转服务。
- 已验证同机两个独立浏览器来源的实际联机及合成 WebSocket 负载。尚未在公网跨运营商、移动网络、高延迟或目标云服务器上验证容量。
- 没有房主迁移；不保证断线期间所有瞬时战斗奖励都可重放。长期断线或服务重启结束当前房间。
- 本版没有自动部署、付费购买或修改生产服务。

# P2P 直连版与中转版

v0.20.0 暂时关闭正式服务的邀请联机和全部房间入口，保留好友、孵蛋及赠礼。以下为保留的 P2P 架构说明；只有内部隔离回归环境显式启用房间功能，正式启动不开放。

## 保留版本

- `v0.15.0` / `codex/relay-v0.15`：原有自建 WebSocket 中转版本，保留源码、构建、测试和 Git 历史。
- `v0.16.0` / 当前 `main`：WebRTC P2P 版本，按 4 核 4GB、3Mbps 预算设计，不提供战斗中转兜底。
- 两者账号数据库结构相同；联机协议不同，中转版为 1、P2P 为 2。浏览器与服务端必须使用同一版本，不支持混合组队。升级前停止服务并备份数据库，升级后刷新网页。切换版本不会自动删除账号或存档。

需要切回时，在工作区无未提交修改、服务已停止和数据库已备份的前提下，切换 `codex/relay-v0.15`，执行 `npm --prefix server ci` 后重新启动。回到 P2P 使用 `main`。不要在同一目录同时运行两个版本或在运行中切换构建文件。

## 数据流

```text
登录、房间、握手、存档、成绩： 玩家 ←HTTPS / WebSocket→ 自建服务器
战斗位置、敌人、技能、掉落：   队员 ←WebRTC DataChannel→ 房主
```

房主分别与最多三名队员建立连接；队员无需互相建立完整网状连接。默认通过公共 STUN 发现地址，服务器以登录 Cookie 校验身份，仅向同房间的合法对象转发 SDP 和 ICE。房主发起每轮协商，随机协商编号隔离旧候选和旧确认，双方都报告数据通道就绪后才能开局。

自建服务器不代理战斗数据：客户端发送 `k:net` 会被服务端拒绝；WebSocket 仅允许固定格式、有限大小和配额的握手。每账号一分钟最多 240 条和 96 KiB 握手输入。只有服务器能发出开局配置，数据通道不能伪造开局或房间消息。没有 TURN 配置，没有 Firebase，也不会借用原作者的服务。

账号和成绩仍需要轻量的持续服务器连接，并非握手后就可断开服务器继续上榜。普通对局每 10 秒发送计时心跳，响应仅包含变化的进度；在线状态每 30 秒更新，不反复上传完整存档。进度更新也校验存档版本，防止后台心跳掩盖其他设备的保存冲突。

## 连接质量与限制

- 房间显示直连状态、往返延迟和“重试直连”；战斗 HUD 显示 P2P 延迟。
- 采用有序可靠数据通道，避免丢失升级、拾取、击杀和结算事件。大消息分片，以避免超过浏览器 SCTP 消息大小限制；组装大小、数量和时限均有上限。
- 短暂故障重新协商，恢复后请求世界同步；约 20 秒仍未恢复则结束对应参与关系。重试不能让已经离队的玩家重新加入同一局。
- 信令连接断开后房间保留约 15 秒；服务器重启、房主长期断线会结束队伍。没有房主迁移，也不保证重放断线间所有瞬时事件。
- 部分 NAT、防火墙、校园网、移动网络组合可能不能直连。此时明确显示失败，需换网络或更换房主；不会自动启用收费中转。STUN 可更换，但不能保证解决所有网络阻挡。
- 房主需要足够的上传带宽，队友可能获知彼此公网 IP。房主仍模拟世界，因此完整战斗防作弊尚未实现。

## 配置与验证

启动方式与自建账号版相同：`npm --prefix server ci`，`node server/server.cjs`。公网使用 HTTPS 反向代理，服务器不需要额外开放 TURN 端口。`STUN_URLS` 是逗号分隔的 STUN 地址列表，最多四个，只接受 `stun:` 和 `stuns:`。

自动测试：`node --test tools/test_server.cjs tools/test_p2p.cjs tools/test_offline.cjs`。

真实浏览器测试：先标准构建，再执行 `node tools/qa_p2p_browser.cjs`。使用隔离内存数据库和独立无头 Edge 配置，验证四人真实 WebRTC、大消息、升级选择、重连、零战斗中转、房主断线，以及最终构建的双人实战。测试用 Playwright 路径与安装方式见 [EVOLUTION_CHOICES.md](EVOLUTION_CHOICES.md)。截图存放在忽略的 `tools/cache/`。

形态与特效回归：`node tools/qa_form_sync.cjs`，在四个隔离浏览器中通过真实进化方向界面选择两段进化，验证每个观察者实际绘制的精灵；同时检查房主/队员 Mega 变身和还原，以及融合 Z 招式的蓄力、投射物、光柱和结束状态。v0.17.0 增加未佩戴 Z 石队员击杀后的全队充能、精英／Boss／事件共享、独立上限及重复奖励检查；使用受控概率调用奖励入口，经实际 P2P 传输发给两个佩戴者。测试只控制隔离样本的等级、能量和奖励概率，不修改玩家存档，也不将调试局提交到公共榜单。

v0.18.0 继续通过相同四人通道验证新增的冲击波、扇形和炮台 Z 在房主及其他队员处可见，结束后清理远端吟唱。所有新类型的视觉副本只展示效果，不重复计算伤害；没有增加新的中转或网络协议。

低带宽控制面测试：`node tools/benchmark_p2p.cjs 100`。该合成测试只衡量账号、握手和在线状态；不衡量公网打洞成功率。真实浏览器验证也仅为本机网络，不代表跨运营商或移动网络结果。具体预算与实测见 [SELF_HOSTING.md](SELF_HOSTING.md)。

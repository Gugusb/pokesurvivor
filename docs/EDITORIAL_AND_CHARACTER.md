# 公告维护与开发角色档案

## 内容边界

本改版的项目角色设定为：Gugusb 负责策划和设计，其个人记忆持久化 Agent「大肥鱼」负责执行实现，二者共同开发；大肥鱼采用 DeepSeek 娘化角色形象。此设定不是对模型身份或官方合作的声明。项目继续基于 JPTER78 的原版，保留原作者、许可证和素材创作者署名。

游戏内公告以玩家能感受到的变化为主，使用简洁、轻松的表达，每篇改版记录末尾使用独立 `note` 字段展示角色收尾。正文、日期、版本与历史语义不能被角色台词改写；原作者的七篇记录不附加改版角色口吻。中文标题与正文维护在 `js/data/lang-zh.js`，西语／英语内容及成对 `note` 维护在 `js/data/changelog.js`，公告渲染统一转义，不插入可执行 HTML。

后续写作约定已纳入根目录 `AGENTS.md`。角色口吻仅用于玩家公告、结算吐槽及角色资料。Git 提交、标签、发布 tips 和 `docs/DEVELOPMENT.md` 保持客观，不加入角色台词。公告源文件仍需正常提交，才能随构建发布。

## 结算对话

`js/data/fish-quips.js` 维护 64 句西／英预设台词，中文放在 `js/data/lang-zh.js`。八组各八句：早期倒下、成长途中、后段失利、胜利收工、通关后继续挑战、阿尔宙斯阶段、个人分数纪录、主动返程。按已有结算数据分类，不推断未知死因，不泄露隐藏机制。阿尔宙斯阶段优先，其后判断已达成目标；通关后死亡使用继续挑战组，避免误判为失败。个人纪录仅表示本地个人分数纪录，不暗示服务器榜单名次。

每次结算在标题与统计之间显示独立卡片，不受原作者赞助提示频率限制。每组在会话内避免连续重复；刷新页面后允许重新抽取，不增加存档字段。通过 `textContent` 写入，已选语言在卡片上禁止再次自动翻译。仅为展示，不改变奖励、通关或排行榜。

## 开发角色账号

使用现有预设角色档案机制，新角色为 `大肥鱼`，固定 ID 通过 `identity('dafeiyu')` 得到。资料显示三个动态伙伴：吼鲸王、美纳斯、卡比兽，并明确注明资料与成绩为预置展示内容。

初始展示记录：64 场冒险、18 只满八枚奖牌宝可梦、最高等级 86、累计击败 183240、首领击败 312、八星最长 32 分 18 秒、冒险最高分 251250。最高分通过现有计分公式生成，全部仅作为角色历史展示，不是服务器验证的玩家实战成绩。

新增账号使用独立随机密码与恢复凭据，仅保存安全哈希，不输出、提交或设置公共默认密码。角色没有管理员权限、没有预置登录会话，也不生成可冒充实战的 `runs`、`run_scores`、`time_scores` 或 `completion_scores`。公开档案通过可信审计标记识别；客户端存档不能自行变成预设角色。现有六个预设角色和真实玩家的展示逻辑保持兼容。

## 指定数据库创建

仅在用户明确指定的目标数据库执行；脚本不会随启动自动修改所有环境。执行前使用既有数据库备份流程保留快照。

```powershell
node server/seed-developer-character.cjs --db 'server/data/game.sqlite'
```

操作在事务中创建用户、存档和角色审计标记。重复执行不覆盖已有记录；名称或固定 ID 与非本工具创建的账户冲突时直接停止，不能覆盖真实用户。脚本摘要只输出账号名称、ID 和展示数值，不包含凭据。

已登录自建账号的用户可从新版公告入口查看档案。目标服务需要同时更新角色目录与档案 API，并执行一次上述命令；仅推送 Git 不会自动修改公网数据库。本地验证只使用内存库和临时账号，实际本地创建操作单独记录。
